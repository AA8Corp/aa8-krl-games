# Kids Robotics Lab — July 2026

**Weekly Focus:** Python Programming Fundamentals with Physical Robotics (building toward future smart robot projects)

**Session Length:** 6:00–8:00 PM (first 10 minutes = meal & settle-in)
**Staffing:** Lead Instructor + 2 Assistants
**Target Group:** Beginner students, ages 9–15 (mixed experience; all coming from block coding; Hello World and a brief intro to variables completed last month)

## The July Arc: "Teach Your Robot to Think"

Three sessions, one story. Each week the students give their "robot" one more ability, and every week ends with something they can *show off*. By the end of the month they can look at Week 1's code and see how far they've come — that's the growth we want to demonstrate.

| Week | Session | Superpower | Big Idea | Take-Home Win |
|------|---------|-----------|----------|---------------|
| 1 | Week 1 | **Memory** | Variables & input/output | A Robot ID Badge program that talks back to you |
| 2 | Week 2 | **Decisions** | `if / elif / else` and booleans | A Robot Brain that reacts to sensor readings |
| 3 | Week 3 | **Movement** | Loops + turtle graphics | A robot they *drive* on screen with real Python commands |

### Why this order works for block-coders

Block coding kids already know the *ideas* (variables, conditionals, loops) — they've just never typed them. Each lesson opens by showing the block version of a concept next to the Python version, so the lesson is "you already know this, here's the grown-up spelling," not "here's something brand new." Week 3's turtle robot uses `forward()`, `left()`, `right()` — the exact same vocabulary as our Robot Freeze brain-break game and the same commands a real robot takes, which is the bridge to physical robotics next month.

### Quick-reward design

Every session follows the same rhythm: students get code **running and doing something visible within the first 15 minutes of hands-on time**, then level it up in small steps. No one stares at a blank editor. Every challenge has a "minimum win" (everyone gets there), a "standard win" (most get there), and "boss level" extensions (keeps the advanced kids hungry without leaving anyone behind).

## Measuring growth across the month

- **Week 1:** each student saves their Robot ID Badge program in Replit — this is their baseline artifact.
- **Week 2 & 3:** each week's project *reuses and extends* skills from the prior week, so the Replit file history is a visible growth record.
- **Week 3 wrap-up:** students open their Week 1 code and read it aloud — "a month ago this looked like magic, now you can explain every line." Great moment to photograph (if permissions on file) and share with parents.
- Exit-ticket question each week (one sentence, verbal or sticky note): "Explain one new thing your code can do." Assistant #2 jots answers on the attendance sheet for the debrief.
